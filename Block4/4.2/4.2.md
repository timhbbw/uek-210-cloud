#### Was ist Redis?
- Redis (Remote Dictionary Server) ist ein Open-Source In-Memory Key-Value Store, also eine nicht-relationale Datenbank (NoSQL).
- Die Daten liegen im Arbeitsspeicher, dadurch sind Lese- und Schreibzugriffe sehr schnell.
- Wird häufig als Cache, Session-Store oder Message Broker eingesetzt.

#### Welche Ports werden in diesem Szenario genutzt und warum?
- 8000 (Host)
    - Wird über `APP_PORT` in der `.env` gesetzt und im `docker-compose.yaml` mit `"${APP_PORT}:5000"` auf den Port 5000 des `web`-Containers weitergeleitet.
    - Über diesen Port wird die App von aussen erreicht: http://localhost:8000
- 5000 (`web`-Container)
    - Standard-Port von Flask (`flask run`), im Dockerfile mit `EXPOSE 5000` dokumentiert.
    - Von aussen nur über das Port-Mapping 8000:5000 erreichbar.
- 6379 (`redis`-Container)
    - Standard-Port von Redis.
    - Wird nicht veröffentlicht (kein `ports:`), dadurch ist Redis nur im internen Compose-Netzwerk erreichbar und von aussen nicht zugänglich.
    - Die App verbindet sich über den Servicenamen als Hostname (`REDIS_HOST=redis`, `REDIS_PORT=6379`).

#### Was ist die Bedeutung von ENV im Dockerfile?
- `ENV` setzt Umgebungsvariablen im Image. Diese gelten für alle folgenden Build-Schritte (z.B. `RUN`) und sind in jedem Container verfügbar, der aus dem Image gestartet wird.
- In diesem Szenario:
    - `FLASK_APP=app.py` legt fest, welche Datei der Befehl `flask run` startet.
    - `FLASK_RUN_HOST=0.0.0.0` lässt Flask auf allen Netzwerk-Interfaces lauschen. Ohne diese Variable lauscht Flask nur auf `127.0.0.1` innerhalb des Containers und wäre über das Port-Mapping nicht erreichbar.
- Die Werte können zur Laufzeit überschrieben werden, z.B. mit `docker run -e` oder `environment:` im `docker-compose.yaml`.
- Abgrenzung: `ENV` wird beim Build ins Image geschrieben (Build-Zeit), `environment:` im `docker-compose.yaml` (hier `REDIS_HOST` und `REDIS_PORT` aus der `.env`) wird erst beim Start des Containers gesetzt (Laufzeit).
